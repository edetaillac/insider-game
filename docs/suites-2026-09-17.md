# Suites après le branchement

## TL;DR

Le jeu est jouable sur téléphone avec les règles de l'ADR. Avant toute nouvelle ligne de code : passer `docs/checklist-mobile.md` sur un iPhone et un Android réels, puis jouer une vraie partie avec la grille d'observation du comité. Les points ci-dessous sont classés par ce qu'ils coûtent si on les ignore.

## À faire avant la première partie réelle

- Passer la checklist mobile (son, Wake Lock, reload, verrouillage, deux onglets, réseau coupé). Deux corrections audio et Wake Lock ont été faites sur relecture, sans test sur appareil
- `TIMER_MS` non numérique donne un chrono qui ne se déclenche jamais, en silence. Ajouter un `Number.isFinite` dans `app.js` ou documenter

## Différés, à traiter au chantier 3

Moteur et vue
- Le libellé de la carte du centre est dupliqué côté client ("Pas de Traître" en dur dans `render.js` pour l'écran de fin, `'center'` en littéral). Exposer dans `view.result` et `view.tallies` des entrées `{ id, name, votes }` nommées par le serveur, et retirer le littéral du client
- `view.result.pointed` n'est pas affiché (qui a été désigné en cas de départage)
- Un id de joueur `__proto__` fausserait `assignRoles` en silence. Les ids sont générés par le serveur, garde d'une ligne si un jour ils viennent de l'extérieur
- Gardes de phase redondantes dans les handlers du moteur, conservées pour le typage TypeScript

Serveur
- `close()` de la table n'empêche pas un `dispatch` ultérieur de réarmer un chrono (atteignable seulement depuis les tests)
- `join` quand le socket est déjà attaché ne répond rien
- Double émission de `state` à l'attache d'un nouveau joueur (payloads identiques)
- L'ordre "kicked avant commit" est un contrat implicite de la table dont dépend le transport. À rendre explicite avant les rooms
- Hôte qui quitte et joueur parti pour de bon : les deux limites acceptées deviendront visibles avec les rooms

Client
- La couleur "urgent" du chrono est sombre sur fond rouge, la spec disait rouge. À trancher à la refonte
- Classes `.tallies`, `.word-form`, `.join-form` sans style dédié
- Entre deux phases chronométrées (playing vers discussion), le chrono affiche `--:--` jusqu'à 250 ms avant le premier tick
- Aucun test automatisé sur `render.js` et `audio.js`. Un test jsdom sur la sortie HTML de `render(view)` et un faux `navigator.wakeLock` auraient attrapé les deux bugs trouvés en revue finale
- Le déblocage audio repose sur des `HTMLAudioElement` joués muets dans le geste. Web Audio (`AudioContext` + `decodeAudioData`) est la voie robuste si iOS pose encore problème

Documentation
- Les captures du README datent de 2020 (dont l'écran admin disparu). À refaire après la refonte

## Recommandations pour les rooms

- `createTable` est déjà une closure par table : `app.js` doit tenir une `Map<roomCode, table>` et le code de room voyage dans `auth` avec le token
- `attached` devient `socketId -> { roomCode, playerId }`
- Garder `data-cmd`, `data-args`, `data-flip`, `data-form` comme contrat stable entre le markup et le comportement : la refonte visuelle remplace les templates et le CSS sans toucher `client.js` ni le serveur

## Critère de go/no-go du comité

Deux parties jouées avec de vrais gens avant fin décembre, avec la liste des douleurs écrite le soir même. Sinon on archive proprement.
